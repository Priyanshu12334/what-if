A full-stack web application that presents a new speculative question every day, lets users vote on outcomes, explore curated what-if scenarios by category, and ask their own what-if questions powered by an AI language model.

## Project Overview

**WHAT IF?** is a daily interactive poll and AI-powered what-if engine. Each day a new question is served to all users. They pick the outcome they think is most likely, see real-time community vote percentages, and read an AI-generated explanation of what might actually happen. Users can also browse 16 curated categories — covering topics from Marvel to Indian mythology to space — and ask their own open-ended what-if questions, with responses generated by a large language model via the Groq API.

---

## Key Features

- **Daily What-If Poll** — One new question per day for all users. Answers are locked to one vote per user per day, with optimistic UI updates and real-time percentage bars.
- **AI-Generated Explanations** — Each daily question includes a 3-sentence AI explanation generated by a Groq-hosted model.
- **Ask AI** — Users can type any what-if scenario and receive a structured AI reply (Answer + Fun fact). Requests are rate-limited to 10 per user per day.
- **Multi-language Support** — The AI detects the question language (English, Hindi/Devanagari, Hinglish) and responds in the same language and script.
- **Streak Tracking** — Users accumulate a daily voting streak that resets if they miss a day.
- **Category Explorer** — 16 hand-curated categories with 15–20 questions each (Marvel, DC, Bollywood, Harry Potter, Star Wars, Anime, Ramayana, Mahabharata, Space, Science, and more). Each category has a photo banner and a searchable accordion list.
- **Ask History** — The last 20 AI questions from the past 7 days are stored per user, with individual or bulk deletion.
- **Authentication** — JWT-based register/login with bcrypt password hashing. Register does not auto-login; users are redirected to login after account creation.
- **Protected Routes** — All app pages require authentication; unauthenticated users are redirected to the landing page.
- **Responsive Design** — Fully responsive across mobile and desktop with a sticky navbar, skeleton loading states, and smooth accordion animations.
- **Rate Limiting** — The `/api/ask` endpoint is rate-limited per user (10 requests / 24 hours) using `express-rate-limit`.

## Installation & Setup

### Prerequisites

- **Node.js** v18 or higher
- **npm** v9 or higher
- **MongoDB** — a running local instance (`mongodb://localhost:27017`) or a MongoDB Atlas connection string

### 1. Clone the repository

```bash
git clone https://github.com/Priyanshu12334/what-if
cd "what-if"
```

### 2. Install backend dependencies

```bash
cd backend
npm install
```

### 3. Configure backend environment variables

```bash
cp .env.example .env
```

Open `backend/.env` and fill in your values (see [Environment Variables](#environment-variables) below).

### 4. Install frontend dependencies

```bash
cd ../frontend
npm install
```

### 5. (Optional) Seed daily questions

If your MongoDB `questions` collection is empty, run the seed script from the `backend/` directory:

```bash
cd ../backend
npm run seed
```

## Environment Variables

### `backend/.env`

Create this file based on `backend/.env.example`:

```env
PORT=5000
MONGO_URI=mongodb://localhost:27017/whatif
JWT_SECRET=your_jwt_secret_key_here
GROQ_API_KEY=your_groq_api_key_here
GROQ_MODEL=your_groq_model_name_here
CLIENT_URL=http://localhost:3000
```

| Variable | Description |
|---|---|
| `PORT` | Port the Express server listens on (default: `5000`) |
| `MONGO_URI` | MongoDB connection string |
| `JWT_SECRET` | Secret used to sign and verify JSON Web Tokens. Use a long random string. |
| `GROQ_API_KEY` | API key from [console.groq.com](https://console.groq.com) |
| `GROQ_MODEL` | Groq model identifier (e.g. the model used for completions) |
| `CLIENT_URL` | Frontend origin allowed by CORS (e.g. `http://localhost:3000`) |

> **Never commit your `.env` file or expose real keys in source control.**

### `frontend` environment variables

The frontend reads the backend URL from Vite's proxy or the Axios base URL defined in `src/api/axios.js`. No `.env` file is required for the frontend in development unless you change the backend port.

## API Overview

All API routes are prefixed with `/api`. Protected routes require a `Authorization: Bearer <token>` header.

### Auth — `/api/auth`

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `POST` | `/api/auth/register` | No | Register a new user. Returns `{ message }`. |
| `POST` | `/api/auth/login` | No | Login. Returns `{ token, user }`. |

### Daily Poll — `/api/daily`

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `GET` | `/api/daily` | Yes | Get today's question, options, vote counts, the user's vote, and their streak. |
| `POST` | `/api/daily/vote` | Yes | Submit or toggle a vote. Body: `{ optionIndex: number \| null }`. Returns updated poll data. |

### Ask AI — `/api/ask`

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `POST` | `/api/ask` | Yes | Submit a what-if prompt. Rate-limited to 10 per user per 24 hours. Body: `{ prompt }`. Returns `{ answer }`. |
| `GET` | `/api/ask/history` | Yes | Get the user's last 20 AI questions from the past 7 days. |
| `DELETE` | `/api/ask/history/:id` | Yes | Delete a single history entry by ID. |
| `DELETE` | `/api/ask/history` | Yes | Delete all history entries for the authenticated user. |

### Categories — `/api/categories`

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `GET` | `/api/categories` | Yes | List all 16 categories (name, slug, group, image, description). |
| `GET` | `/api/categories/random` | Yes | Return one random question from a random category. |
| `GET` | `/api/categories/:slug` | Yes | Return full category data including all questions and answers. |

## Future Improvements

- **User profiles** — Display vote history, total questions asked, and streak statistics on a profile page.
- **Comments / reactions** — Let users leave a short comment or emoji reaction on the daily question.
- **Push notifications** — Browser or email reminders to maintain a voting streak.
- **Admin dashboard** — A protected panel to create, edit, and schedule daily questions without touching the database directly.
- **Leaderboard** — Rank users by longest current streak or total days voted.
- **Shareable cards** — Generate a shareable image for a user's answer or category question.
- **Search** — Global search across all categories and questions.
- **More categories** — Expand the content library with new themes (sports, literature, gaming, etc.).
- **Offline support** — Cache the daily question via a service worker so users can read it without internet.
